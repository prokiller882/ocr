# SnapOCR

Windows-утилита для офлайн-распознавания текста со скриншотов: глобальный хоткей, выделение области экрана и мгновенное распознавание. Результат можно редактировать и копировать, история сохраняется. Всё работает локально: без интернета и без отправки данных на сторонние серверы.

## Зачем это нужно

Готовые OCR-инструменты часто плохо справляются со скриншотами, где текст наклонён, снят под углом или имеет перспективные искажения. SnapOCR решает это ещё на этапе выделения области:

- **Поворот области** — выделение можно повернуть на любой угол; после подтверждения изображение автоматически выпрямляется, и наклонный текст распознаётся точнее.
- **Четырёхугольник** — свободное выделение по четырём углам с перспективным исправлением: удобно для трапециевидных и искажённых областей.
- **Автоопределение ориентации текста** — каждая найденная строка проверяется в четырёх положениях: обычном, перевёрнутом на 180°, зеркальном и зеркальном с поворотом на 180°. Выбирается вариант с наибольшей уверенностью, поэтому перевёрнутый или отзеркаленный текст распознаётся правильно без ручной настройки.

Для распознавания используется [ppocrv6_onnx](https://github.com/AIwork4me/ppocrv6_onnx) — локальный ONNX-движок на базе [PaddleOCR](https://github.com/PaddlePaddle/PaddleOCR).

## Возможности

- ⚡ Глобальный хоткей (по умолчанию `Ctrl+Alt+Z`) или двойной клик по иконке в трее.
- 🖱️ Оверлей выделения в стиле WeChat / QQ: светлая область или полупрозрачный серый фон.
- 📐 Перемещение, изменение размера и поворот выделения; `Shift` включает привязку к 15°.
- 🔷 Режим четырёхугольника: четыре угла вручную, перспективное исправление перед OCR.
- 🔄 Автоматическая проверка ориентации: обычный, перевёрнутый, зеркальный и зеркальный + перевёрнутый текст.
- 📝 Окно результата: исходный снимок и редактируемый текст, копирование в один клик, время распознавания.
- 🕘 История: автоматическое сохранение, миниатюры, листание, удаление записи и полная очистка с подтверждением.
- ⚙️ Настройки: хоткей, автокопирование, лимит истории, параметры OCR (модели, пороги, предобработка).
- 🔒 Полностью офлайн: модели входят в комплект, облачные API не используются.
- 🇷🇺 Русский интерфейс.

## Требования

- Windows 10/11 (x64). Приложение работает только на Windows.
- Python 3.10+ — только для запуска из исходников.
- Для готового `SnapOCR.exe` Python не нужен.

## Установка и запуск из исходников

```bash
# 1. Клонировать репозиторий
git clone https://github.com/openuser-design/snap_ocr.git
cd snap_ocr

# 2. Установить зависимости
#    requirements.txt устанавливает OCR-движок из локального wheel-файла
pip install -r requirements.txt

# 3. Запустить
python run.py
```

`requirements.txt` первой строкой подключает локальный wheel `ppocrv6_onnx-1.0.0-py3-none-any.whl`. Заменять его на пакет из PyPI не нужно.

## Готовая сборка

В репозитории уже есть собранное приложение:

```
dist\SnapOCR.exe
```

Это один самодостаточный файл (~95 МБ) с иконкой, моделями OCR и всеми зависимостями. Запускается двойным кликом; Python и установка пакетов не требуются.

- При первом запуске рядом с exe создаются `config.json`, `history.json` и `app.log`.
- Папку с exe можно перенести в любое место, где есть право записи. В `Program Files` без прав администратора приложение не сможет создать свои файлы.
- Exe не подписан, поэтому SmartScreen может показать предупреждение: «Подробнее» → «Выполнить в любом случае».
- Чтобы создать ярлык, используйте правый клик по exe → «Отправить» → «Рабочий стол (создать ярлык)». Иконка приложения подхватится автоматически.

## Использование

1. После запуска приложение остаётся в системном трее.
2. Нажмите `Ctrl+Alt+Z` (комбинацию можно изменить в настройках) или дважды кликните по иконке в трее.
3. Выделите область: после отпускания кнопки мыши её можно перемещать, масштабировать и поворачивать.
4. Для наклонного или перспективно искажённого текста включите на панели режим **«Четырёхугольник»** и перетащите четыре угла по границам текста.
5. Нажмите `Enter`, дважды кликните внутри области или выберите **«Готово»** — запустится распознавание.
6. В окне результата текст можно редактировать; кнопка **«Копировать всё»** отправляет его в буфер обмена.
7. Меню трея: **«Снимок экрана»**, **«История»**, **«Настройки»**, **«Выход»**.

Ориентация текста (перевёрнутый, зеркальный, зеркальный + перевёрнутый) определяется автоматически — отдельной настройки нет.

## Настройки

- **Горячая клавиша** — глобальная комбинация для запуска захвата.
- **Автоматически копировать в буфер обмена** — копировать результат сразу после распознавания.
- **Стиль выделения** — светлый или полупрозрачный серый.
- **Язык распознавания** — китайский + английский (возможности модели; русский текст OCR не поддерживает).
- **Лимит истории** — от 10 до 50 записей.
- **Масштаб** — 10–500 % (100 % — исходный размер; мелкий текст можно увеличить).
- **Отступ по краям** — 0–200 px, чтобы текст у границ области попадал в кадр целиком.
- **Модели** — `det.onnx`, `rec.onnx`, `chars.txt`. Пустые поля означают встроенные модели; можно указать свои файлы.
- **Порог бинаризации**, **порог рамки**, **коэффициент расширения** — тонкая настройка детекции.
- **Размер батча** — 1–32, компромисс между памятью и скоростью.

## Автоматическая ориентация текста

Для каждой найденной строки движок распознаёт четыре варианта кропа:

1. как есть;
2. поворот на 180°;
3. зеркало по горизонтали;
4. зеркало по горизонтали + поворот на 180° (то же, что зеркало по вертикали).

Затем выбирается результат с наибольшей уверенностью. Рамки и порядок строк не меняются, поэтому окно результата, история и навигация работают как раньше.

Детекция выполняется один раз, распознавание — для четырёх вариантов, поэтому время распознавания увеличивается, но повторной детекции нет. Проверка выполняется всегда; в настройках её нет. Поскольку детектор предварительно выпрямляет область по минимальному ограничивающему прямоугольнику, эти четыре варианта покрывают также повороты на 90°/270° и произвольные углы — при условии, что детектор нашёл строку.

Ограничение: для принципиально неоднозначных симметричных строк вроде `NO` / `ON` невозможно определить замысел без контекста — будет выбран более уверенный вариант.

## Сборка exe

Сборка выполняется на Windows через PyInstaller. Все зависимости и PyInstaller должны быть установлены в используемом Python.

Самый простой способ — запустить `build.bat`:

```bat
build.bat
```

Либо выполнить команду вручную:

```bat
python -m PyInstaller --noconfirm --clean build.spec
```

Результат: `dist\SnapOCR.exe`.

`build.spec` уже содержит:

- сборку в один файл (`onefile`) без консольного окна;
- `collect_all("ppocrv6_onnx")` — код движка, модели `det.onnx`, `rec.onnx` и словарь `chars.txt`;
- скрытый импорт `pystray._win32`;
- иконку `assets/snapocr.ico`;
- отключённый UPX;
- защиту от устаревших `MSVCP140.dll` / `VCRUNTIME140.dll` из сторонних JRE в `PATH`: в сборку берутся актуальные версии из `C:\Windows\System32`.

`build/` и `dist/` — стандартные каталоги PyInstaller; исходный код они не меняют.

## Технологии

- **Язык**: Python 3.10+
- **Интерфейс**: Tkinter (стандартная библиотека)
- **OCR**: ppocrv6_onnx (локальный wheel, включает onnxruntime / OpenCV / NumPy / pyclipper)
- **Трей**: pystray
- **Снимок экрана / иконки**: Pillow
- **Глобальный хоткей**: Windows `RegisterHotKey` через `ctypes`
- **Сборка**: PyInstaller

## Структура проекта

```
snap_ocr/
├── main.py            # Точка входа: сборка App + главный цикл Tk
├── config.py          # Модель настроек: чтение/запись config.json
├── cores/             # База: пути, логирование, глобальный хоткей
└── modules/           # Логика: трей, OCR, захват, история, окна
run.py                 # Запуск из исходников
requirements.txt       # Зависимости (локальный wheel OCR)
build.spec             # Конфигурация PyInstaller
build.bat              # Сборка exe двойным кликом
assets/snapocr.ico     # Иконка приложения и ярлыка
dist/SnapOCR.exe       # Готовая сборка
```

## Данные и конфиденциальность

В каталоге запуска создаются ровно три файла:

- `config.json` — настройки;
- `history.json` — история распознаваний, включая JPEG-снимки в base64;
- `app.log` — журнал приложения с ротацией.

Приложение не обращается к сети. Историю можно очистить целиком или удалять отдельные записи через окно **«История»**.

## Ограничения

- OCR-модель понимает только китайский и английский текст; русский язык распознавания не поддерживается.
- Очень сильно искажённый или низкоконтрастный текст может не обнаружиться детектором — автоматическая ориентация помогает только тогда, когда строка уже найдена.
- Готовый exe не подписан: возможен запрос SmartScreen или предупреждение антивируса. При блокировке onefile можно собрать приложение в режиме `onedir` (папка с exe и DLL).
